figma-to-design-md

CLIopen source

Агенту нужна спецификация рядом с кодом, а не ссылка на макет, который он не откроет. Инструмент читает файл Figma и записывает в markdown переменные, компоненты и то, что в файле есть, а в описании ещё нет.

Репозиторий на GitHub

Установка

# Запустить сразу
npx figma-to-design-md extract --file <key> --token <token>

# Или установить глобально
npm i -g figma-to-design-md

Настройка

1. Возьми токен Figma

Открой настройки Figma. Зайди в Personal access tokens и создай токен с правом File content: Read-only.

2. Возьми ключ файла

Из любой ссылки на файл в Figma:

https://www.figma.com/design/ABC123xyz/My-Design-System
                              ^^^^^^^^^^^
                              это ключ файла

3. Запусти

figma-to-design-md extract \
  --file ABC123xyz \
  --token figd_xxx

ФлагПо умолчаниюОписание

Если у переменной несколько режимов, например Light и Dark, в файл попадают все значения.

Пробелы и передача в контекст

Инструмент сам замечает пустые места в файле Figma и пишет их в gaps.md:

  • Нет описанийУ компонентов нет описания в Figma. Агент не понимает, для чего они.
  • Нет токеновВ файле нет локальных переменных. Markdown получится неполным.
  • Компоненты без документацииКомпоненты есть, а описания для агента нет.

После того как пробелы заполнены, полученные markdown-таблицы можно напрямую подать в ds-lint (флаг --tokens) или упаковать под бюджет токенов через ds-context.
