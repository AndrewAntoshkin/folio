prompt-regress

Регрессияopen source

Новая версия промпта редко оказывается лучше сразу во всём. Она может починить выпадающий список и сломать окно, где человек подтверждает удаление. prompt-regress сравнивает два прогона одних и тех же экранов и показывает, что стало лучше, что сломалось и почему. На странице — сравнение 16 заранее записанных примеров, без запуска модели.

Репозиторий на GitHub
prompt-regress

Зачем

Новая версия системного промпта редко оказывается лучше сразу во всём. Одним экранам она помогает, другим вредит: модель начинает использовать компонент Select и при этом забывает опасный стиль у кнопки удаления. По среднему баллу этого не видно.

prompt-regress сравнивает версии промпта и показывает разницу по каждому примеру. Берёт заранее записанный прогон, как ds-eval.

Промпты

prompts/v12.md просит делать быстро и разрешает обычный элемент браузера, если компонент системы неясен.

You build the screen from the design system.
Prefer speed. If a system component is unclear, use a native control.

prompts/v13.md называет компоненты и запрещает тег button, цвет в hex и самодельную модалку. Если кейс спорит с системой, промпт велит следовать системе.

You build the screen from the design system.
Use Button, Input, Select, and Dialog. Never emit a raw button, a hardcoded hex color, or a custom modal.
If a case conflicts with the system, follow the system and say so.

Запуск

python3 prompt-regress/prompt_regress.py diff \
  prompt-regress/prompts/v12.md \
  prompt-regress/prompts/v13.md

По имени промпта берётся JSON прогона: prompts/v12.md читает runs/v12.json. В кейсе лежат pass, балл DS, токены и заметка. В этом прогоне скриншота нет. Поле можно добавить, когда прогон его сохранит.

Дифф

Кейс помечается improved или regressed, если он начал или перестал проходить, или если балл DS сдвинулся на 10 пунктов и больше. Иначе метка unchanged.

УсловиеМетка
перестал проходить, или балл DS упал на 10 пунктов и большеregressed
начал проходить, или балл DS вырос на 10 пунктов и большеimproved
pass не изменился, и балл DS сдвинулся меньше чем на 10 пунктовunchanged

На 16 сохранённых кейсах команда печатает:

v12 → v13
6 improved / 2 regressed / 8 unchanged
tokens  26270 → 26230

Колонка токенов — сумма из сохранённого прогона, а не счёт из API.

Запись

Один кейс в двух прогонах. Поля одни и те же: id, pass, ds, tokens, note.

{
  "v12": {
    "id": "select-001",
    "pass": false,
    "ds": 38,
    "tokens": 1640,
    "note": "Native select, no label."
  },
  "v13": {
    "id": "select-001",
    "pass": true,
    "ds": 91,
    "tokens": 1720,
    "note": "Select with a label."
  }
}

Связь с остальными инструментами

ds-context фиксирует, какой контекст видела модель. ds-eval ставит балл кейсу. prompt-regress сравнивает два таких прогона, когда меняется промпт, пакет контекста или модель. Регрессия здесь — не падение общего числа, а список кейсов, которые изменились.

Предел

Команда не запускает модель и не рисует интерфейс. Заметки и баллы лежат в JSON, который записан заранее. Пока нет скриншотов, объяснение — одна строка на кейс. 6 / 2 / 8 относится к этим 16 сохранённым кейсам, а не к набору из ста задач.
