ds-coverage

Сканерopen source

Система может быть большой, а экраны рядом всё равно собраны из своих кнопок и окон. ds-coverage смотрит импорты и показывает, что из системы реально используется, что не используется и где рядом написали свою копию.

Репозиторий на GitHub
ds-coverage

Зачем

В репозитории может лежать дизайн-система на сорок компонентов, а продуктовые экраны рядом всё равно собирают из своих Button и Modal. На ревью это всплывает поздно.

ds-coverage проходит по импортам и показывает три вещи: какие компоненты системы реально используются, какие лежат мёртвым грузом и где в продукте написали локальный дубль с тем же именем.

Установка

# Run directly (no install)
npx @andrewaitken/ds-coverage src/ --ds @acme/ui

# Or install globally
npm i -g @andrewaitken/ds-coverage

Запуск

# Basic scan
ds-coverage src/ --ds @acme/ui

# Multiple packages
ds-coverage . --ds @acme/ui,@acme/icons

# With component inventory (finds unused)
ds-coverage src/ --ds @acme/ui --inventory components.json

# Markdown report
ds-coverage src/ --ds @acme/ui --format markdown --out coverage.md

# CI threshold (fail below 70%)
ds-coverage src/ --ds @acme/ui --inventory components.json --min 70

Параметры

ФлагПо умолчаниюОписание
[path].Папка для проверки
--ds <packages>—Имена пакетов системы через запятую (обязательно)
--inventory <file>—JSON со всеми компонентами системы
--format <type>terminalterminal | markdown | json
--out <file>—Записать отчёт в файл
--min <percent>—Ошибка, если покрытие ниже порога
--versionПоказать версию
--helpПоказать справку

Что измеряет

  • Используемые компонентыСколько компонентов из инвентаря системы хотя бы раз импортировано в коде
  • Всего импортовСколько раз пакет системы импортировали по файлам проекта
  • Локальные компонентыКомпоненты из относительных путей — кандидаты на вынос в систему
  • Дубли по имениЛокальные компоненты с тем же именем, что у системных — сигнал возможной повторной реализации
  • НеиспользуемыеЭкспорты системы, которые нигде не импортированы (нужен --inventory)

Под «покрытием» здесь понимается именно доля задействованного каталога системы (например, 34 из 39 экспортируемых компонентов = 87%) и карта совпадений имён, а не оценка визуального качества экранов.

Инвентарь

Чтобы найти неиспользуемые компоненты, передай JSON со всеми экспортами пакета системы:

Формат массива

["Button", "Card", "Modal", "Tooltip", "Badge", "Input", "Select"]

Формат объекта

{
  "components": ["Button", "Card", "Modal", "Tooltip", "Badge"]
}

Можно указать index-файл пакета: ds-coverage сам разберёт экспорты.

CI

# GitHub Actions
- name: Check DS adoption
  run: npx @andrewaitken/ds-coverage src/ --ds @acme/ui --inventory components.json --min 60

# Generate PR report
- name: DS Coverage Report
  run: npx @andrewaitken/ds-coverage src/ --ds @acme/ui --format markdown --out coverage.md

--min завершается с кодом 1, если покрытие ниже порога.
